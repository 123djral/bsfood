# 系统架构与功能调用链文档

> 本文档面向开发者与答辩评审，提供两部分内容：
> 1. **系统整体架构**：技术选型、分层职责、部署拓扑、核心流程时序。
> 2. **功能调用链**：对每一个用户可触达的功能，按照 "前端视图 → 前端 API → 后端 Controller → Service/Impl → Mapper/工具类/外部 API → 数据库/资源" 的顺序，给出精确到类名与方法名的调用路径。

## 第一部分：系统整体架构

### 1.1 技术栈概览

| 层次 | 技术 | 版本/说明 |
|------|------|----------|
| 前端框架 | Vue.js | 3.x（Composition + Options 混用） |
| 前端 UI | Element Plus | 与 Vue 3 搭配 |
| 前端构建 | Vite | 4.x，`vite.config.js` 中把 `/api` 代理到 `http://localhost:8080` |
| 前端路由 | Vue Router | 5.x，含 `beforeEach` 导航守卫 |
| HTTP 客户端 | Axios | 统一封装于 `src/api/index.js`，自动注入 JWT |
| 后端框架 | Spring Boot | 3.2.0 |
| ORM | MyBatis-Plus | 3.5.x，Mapper 继承 `BaseMapper<T>` |
| 安全框架 | Spring Security 6 + JWT (jjwt) | `SecurityConfig` + `JwtAuthFilter` |
| 关系数据库 | MySQL | 8.0（`recipe_generator`） |
| 缓存 | Redis | 6.x/7.x（当前用于用户偏好缓存；另有进程内缓存用于营养分析） |
| AI 文本/食谱/营养 | MiniMax-M2.7 Chat Completions | `https://api.minimaxi.com/v1/chat/completions` |
| AI 图像生成 | MiniMax `image-01` | `/v1/image_generation`，本地落盘到 `picture/` |
| AI 图像识别（主） | Qwen-VL Plus (`qwen3-vl-plus`) | 阿里云百炼 DashScope，OpenAI 兼容模式 |
| AI 图像识别（备选） | Claude CLI MCP | `McpImageClient` 调用 `scripts/claude_image_client.py` |
| 运行时 | Java | 17 |

### 1.5 数据库模型

| 表 | 关键字段 | 关系 |
|----|----------|------|
| `user` | id, username, password (BCrypt), role (USER/ADMIN), age, gender, phone, create_time | 用户主表 |
| `user_preference` | id, user_id, taste_preference, cooking_level, diet_limit, health_goal, max_cooking_time | `user` 1:1 |
| `food_material` | id, user_id, name, type, quantity (g), shelf_life (days), nutrition_id, create_time | `user` 1:N，`nutrition` N:1 |
| `recipe` | id, user_id, name, english_name, image_keyword, image_url, cooking_time, difficulty_level, steps, food_ids(字符串), collect_count, ingredients, tools, tips, suitable_crowd, cuisine_style, flavor_profile, servings, nutrition_brief, create_time | `user` 1:N |
| `user_collection` | id, user_id, recipe_id, create_time | `user` N:M `recipe` 的中间表 |
| `nutrition` | id, food_id, calorie, protein, fat, carbohydrate, vitamin, mineral | 食材营养词典 |

> `recipe.food_ids` 以字符串（例：`"[1, 2, 3]"`）保存，营养分析时使用正则剥离方括号后按逗号切分，非关系型外键。

### 1.6 核心业务时序

**(a) 生成一份食谱（最核心的业务流程）**

```
Recipe.vue                             后端                             MiniMax
   │ 1. 选择食材 + 期望数量                │
   │────recipeApi.generate─────────────▶ RecipeController.generate
   │                                     │
   │                                     │ recipeService.generateRecipe(foodIds,userId,expectCount)
   │                                     │   ├─ foodMaterialMapper.selectById × N   (取食材名+克数)
   │                                     │   ├─ userService.getPreference(userId)   (口味/健康目标/饮食限制)
   │                                     │   ├─ 冲突检查：食材名 ∩ dietLimit
   │                                     │   ├─ aiApiClient.generateRecipe(...) ──────▶ Chat Completions
   │                                     │   │                                    ◀── JSON 数组
   │                                     │   └─ recipeMapper.insert × N          (落库，附加 food_ids, createTime)
   │◀────食谱列表 JSON──────────────────────│
   │                                     │
   │ 2. 用户点开详情，触发配图             │
   │────recipeApi.generateImage(id)────▶ RecipeController.generateImage
   │                                     │   ├─ recipeService.getRecipeById(id)
   │                                     │   ├─ imageDownloader.getLocalImagePath(name)  ← 命中则直接回写 image_url 结束
   │                                     │   ├─ aiApiClient.generateRecipeImage(...) ──▶ image-01
   │                                     │   │                                       ◀── 图片 URL
   │                                     │   ├─ imageDownloader.downloadAndSaveImage(...) (写入 picture/<name>.jpg)
   │                                     │   └─ recipeService.updateRecipe(recipe)       (image_url 落库)
   │◀────imageUrl = /picture/xxx.jpg───────│
```

**(b) 图片识别食材**

```
Food.vue  ──foodApi.recognize({text:"",image:DataURL,type:"image"})──▶ FoodController.recognize
                                                                         │
                                                                         │ foodService.recognizeFood(...,type,userId)
                                                                         │   ├─ "image"/"mix": aiApiClient.recognizeImageFood(image)
                                                                         │   │    └─ callImageUnderstandApi
                                                                         │   │         ├─ dashscopeApiKey 有效 → callQwenVlImageUnderstand ──▶ Qwen-VL Plus
                                                                         │   │         └─ 否则           → callMiniMaxImageUnderstand
                                                                         │   ├─ "text": aiApiClient.recognizeTextFood(text)
                                                                         │   └─ foodMaterialMapper.insert × N (绑定 userId)
                                                                         ▼
                                                                     JSON: {foodList:[...]}
```

**(c) 登录与鉴权**

```
Login.vue ─userApi.login─▶ POST /api/user/login
                             └─ UserController.login
                                  ├─ userService.login(username,password)
                                  │     ├─ userMapper.selectOne by username
                                  │     └─ passwordEncoder.matches(...)
                                  └─ jwtUtil.generateToken(userId,username)  →  返回 {token, userId, username, role}

后续请求 ─Bearer Token─▶ JwtAuthFilter.doFilterInternal
                             ├─ jwtUtil.getUserIdFromToken
                             ├─ jwtUtil.validateToken
                             └─ SecurityContextHolder 设置 authentication
```

## 第二部分：功能调用链（前端 → 后端 → 外部）

> **读法**：每个功能块列出触发视图 → 前端 API 封装 → HTTP 请求 → 后端 Controller → 业务 Service → Mapper/工具/外部 → 数据存储。
> 标注格式：`类名.方法名()`。

### 2.1 用户管理模块

#### 2.1.1 注册

| 阶段 | 位置 | 说明 |
|------|------|------|
| 视图 | `Login.vue` (isRegister=true) | 提交用户名/密码/年龄/性别/手机号 |
| 前端 API | `userApi.register(user)` in `api/index.js` | `POST /api/user/register`，body=User |
| Controller | `UserController.register(User)` | `@PostMapping("/register")` |
| Service | `UserServiceImpl.register(User)` | 检查用户名唯一 → `passwordEncoder.encode` → `userMapper.insert` |
| 签发 Token | `JwtUtil.generateToken(userId, username)` | 注册成功后立即返回 Token |
| 数据 | `user` 表插入一条，`role="USER"` | — |

#### 2.1.2 登录

| 阶段 | 位置 | 说明 |
|------|------|------|
| 视图 | `Login.vue` | — |
| 前端 API | `userApi.login(username, password)` | `POST /api/user/login?username=..&password=..` |
| Controller | `UserController.login(username, password)` | `@PostMapping("/login")` |
| Service | `UserServiceImpl.login(username, password)` | `userMapper.selectOne` + `passwordEncoder.matches` |
| 签发 Token | `JwtUtil.generateToken(userId, username)` | 返回 `{token, userId, username, role}` |
| 前端副作用 | `localStorage.setItem('token',...)` 及 user | 触发下一次请求自动带 Token |

#### 2.1.3 获取当前登录用户

| 阶段 | 位置 | 说明 |
|------|------|------|
| 视图 | `App.vue` / 任意页初始化 | — |
| 前端 API | `userApi.getCurrentUser()` | `GET /api/user/me`，头携带 Bearer |
| Controller | `UserController.getCurrentUser(Authorization)` | 解析 Bearer，取 userId |
| Service | `UserServiceImpl.getUserById(userId)` | `userMapper.selectById` |
| 工具 | `JwtUtil.getUserIdFromToken` | — |

#### 2.1.4 更新个人资料

`User.vue` → `userApi.update(user)` → `PUT /api/user/update` → `UserController.update` → `UserServiceImpl.update` → `userMapper.updateById`。

#### 2.1.5 读取 / 更新饮食偏好

- 读取：`User.vue` → `userApi.getPreference(userId)` → `GET /api/user/preference` → `UserController.getPreference` → `UserServiceImpl.getPreference` → Redis (`user:preference:<id>`) 命中则返回；否则 `userPreferenceMapper.selectOne` 回填缓存。
- 更新：`userApi.updatePreference(preference)` → `PUT /api/user/preference` → `UserController.updatePreference` → `UserServiceImpl.updatePreference` → `userPreferenceMapper.insertOrUpdate` → 清除 Redis 缓存。

### 2.2 食材管理模块

#### 2.2.1 AI 识别食材（文本/图片/混合）

| 阶段 | 位置 | 说明 |
|------|------|------|
| 视图 | `Food.vue` | 用户输入文本或上传图片（转 Base64 DataURL） |
| 前端 API | `foodApi.recognize(text, image, type, userId)` | `POST /api/food/recognize`，JSON body |
| Controller | `FoodController.recognize(payload,...)` | 兼容 body + query，整合为 text/image/type/userId |
| Service | `FoodServiceImpl.recognizeFood(text, image, type, userId)` | 分支：`text` / `image` / `mix` |
| 外部 | `AiApiClient.recognizeTextFood`（text 分支） | MiniMax Chat Completions |
| 外部 | `AiApiClient.recognizeImageFood`（image/mix 分支） | `callImageUnderstandApi` |
|  | ↳ `AiApiClient.callQwenVlImageUnderstand` | 优先：阿里云百炼 Qwen-VL Plus |
|  | ↳ `AiApiClient.callMiniMaxImageUnderstand` | 兜底：MiniMax vision |
| 可选备选 | `McpImageClient.recognizeImageViaMcp` | 通过 Python 脚本调 Claude CLI MCP（需外部环境） |
| 落库 | `foodMaterialMapper.insert` ×N | 绑定 `user_id`、`create_time` |
| 返回 | `{foodList:[FoodMaterial], status:"success"}` | — |

#### 2.2.2 食材 CRUD

| 操作 | 前端 | 后端链路 |
|------|------|---------|
| 保存单条 | `foodApi.save(food,userId)` | `POST /api/food/save` → `FoodController.save` → `FoodServiceImpl.saveFood` → `foodMaterialMapper.insert` |
| 分页列表 | `foodApi.list(userId,keyword,page,size)` | `GET /api/food/list` → `FoodController.getList` → `FoodServiceImpl.searchFoods` → `foodMaterialMapper.selectPage` |
| 全量列表 | `foodApi.listAll(userId)` | `GET /api/food/all` → `FoodController.getAllFoods` → `FoodServiceImpl.getFoodList` → `foodMaterialMapper.selectList` |
| 详情 | `foodApi.detail(id,userId)` | `GET /api/food/detail` → `FoodController.getDetail` → `FoodServiceImpl.getFoodById` |
| 更新 | `foodApi.update(food,userId)` | `PUT /api/food/update` → `FoodController.update` → `FoodServiceImpl.updateFood` |
| 删除 | `foodApi.delete(id,userId)` | `DELETE /api/food/delete` → `FoodController.delete` → `FoodServiceImpl.deleteFood` |

#### 2.2.3 食材营养数据

`Food.vue` → `foodApi.nutrition(foodId)` → `GET /api/food/nutrition` → `FoodController.getNutrition` → `FoodServiceImpl.getNutritionByFoodId` → `nutritionMapper.selectOne(foodId)`。

#### 2.2.4 食材替代方案

- 按 ID：`foodApi.substitute(foodId)` → `FoodController.getSubstitute` → `FoodServiceImpl.getSubstituteFood` → AI 生成候选 → 过滤入库同类食材。
- 按名称/类型：`foodApi.substituteByName(name,type)` → `FoodController.getSubstituteByName` → `FoodServiceImpl.getSubstituteByName` → `AiApiClient` 生成候选列表。

### 2.3 食谱生成模块

#### 2.3.1 AI 生成食谱

| 阶段 | 位置 | 说明 |
|------|------|------|
| 视图 | `Recipe.vue` | 选择食材 + 期望份数（1-5） |
| 前端 API | `recipeApi.generate(userId, foodIds, expectCount)` | `POST /api/recipe/generate?userId=&foodIds=a,b&expectCount=3` |
| Controller | `RecipeController.generate` | `@PostMapping("/generate")` |
| Service | `RecipeServiceImpl.generateRecipe` | |
| ↳ 预处理 | `foodMaterialMapper.selectById` ×N | 组装 `"名字 克数g"` |
| ↳ 偏好 | `userService.getPreference(userId)` | Redis 优先 |
| ↳ 冲突校验 | 比对 `diet_limit` | 命中抛 `IllegalArgumentException` |
| ↳ 调用 AI | `AiApiClient.generateRecipe(foodNames, userId, expectCount, difficultyLevel, tastePreference, cookingLevel, maxCookingTime, dietLimit, healthGoal)` | MiniMax-M2.7 |
| ↳ 解析 | `extractJson` + `parseRecipeListFromJson` | 兜底 `fixMalformedJson` |
| ↳ 落库 | `recipeMapper.insert` ×N | `food_ids = foodIds.toString()` |
| 返回 | `{code:200, data:{recipeList}}` | — |

#### 2.3.2 配图（AI 生成 + 本地缓存）

| 阶段 | 位置 | 说明 |
|------|------|------|
| 视图 | `Recipe.vue` 详情 / `Collection.vue` | 缺图时触发 |
| 前端 API | `recipeApi.generateImage(id)` — 实现侧内嵌于页面 axios 调用（`POST /api/recipe/generateImage?id=`） | 详情页拉起 |
| Controller | `RecipeController.generateImage(id)` | |
| 先查本地 | `ImageDownloader.getLocalImagePath(recipeName)` | 命中→仅更新 `image_url` |
| 调 AI | `AiApiClient.generateRecipeImage(name, englishName, imageKeyword)` | POST `/v1/image_generation`，模型 `image-01` |
| 下载落盘 | `ImageDownloader.downloadAndSaveImage(aiUrl, recipeName)` | 保存到 `C:/develop/codeBase/bsfood1/picture/` |
| 更新 | `recipeService.updateRecipe(recipe)` | `recipe.image_url = /picture/<safeName>.jpg` |
| 静态服务 | `WebMvcConfig.addResourceHandlers` | `/picture/**` → 本地目录 |
| 安全放行 | `SecurityConfig.filterChain` 允许 `/picture/**` | 匿名可读 |

### 2.4 营养分析模块

| 阶段 | 位置 | 说明 |
|------|------|------|
| 视图 | `Nutrition.vue` | 选择食谱 |
| 前端 API | `nutritionApi.analyze(recipeId)` | `GET /api/nutrition/analyze?recipeId=` |
| Controller | `NutritionController.analyze(recipeId)` | |
| Service | `NutritionServiceImpl.analyzeNutrition(recipeId)` | |
| ↳ | `recipeMapper.selectById` | 取食谱名称与步骤 |
| ↳ | 解析 `recipe.food_ids` → `foodMaterialMapper.selectById` ×N | 组装食材名列表 |
| ↳ AI | `AiApiClient.analyzeNutrition(name, steps, foodNames)` | 返回 JSON 对象（含 calorie、protein、fat、carbohydrate、评估、建议） |
| ↳ | `Jackson.ObjectMapper.readValue` | 反序列化为 `Map<String,Object>` |
| 可选 | `NutritionCacheService.get / put` | 按排序后食材 ID 的 MD5 键缓存 1h（当前在 Service 层留有钩子） |
| 返回 | `{code:200, data:{...}}` | — |

单表 CRUD：

## 第三部分：可扩展与改进点（供评审讨论）

1. **管理员接口鉴权**：目前 `/api/admin/**` 仅前端路由守卫，未在 `SecurityConfig` 中校验角色；可在 `JwtAuthFilter` 中将 `role` 写入 `GrantedAuthority` 后在 `SecurityConfig` 加 `.hasRole("ADMIN")`。
2. **`recipe.food_ids` 以字符串存储**：对后续按食材做联合查询不友好，可迁移到 `recipe_food` 中间表。
3. **营养分析缓存未在 Service 中被调用**：已有 `NutritionCacheService` 但 `NutritionServiceImpl.analyzeNutrition` 尚未串联其 `generateKey/get/put`，接入即可减少重复 AI 调用。
4. **异步生成任务**：`AsyncTaskService` 提供了任务状态机，控制器侧可新增 `POST /api/recipe/generateAsync` + `GET /api/recipe/task/{id}` 以解耦请求与 AI 耗时。
5. **图片路径硬编码**：`WebMvcConfig` 与 `ImageDownloader` 均写死 `C:/develop/codeBase/bsfood1/picture`，部署到 Linux 时需抽取到 `application.yml`。
6. **`McpImageClient` 依赖外部 Claude CLI**：跨机部署难度高，生产环境建议只保留 Qwen-VL / MiniMax 双通道。
